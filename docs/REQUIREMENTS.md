# Requirements

Each requirement has an acceptance criterion and a verification pointer: a test module
under `tests/`, a manual check in `docs/TEST_PLAN.md` (M-n), or a code/doc inspection.
Requirements changed or added in v0.2.0 are marked (v0.2).

## Functional

| ID | Requirement | Acceptance criterion | Verified by |
|---|---|---|---|
| FR-1 | Plug-and-play dongle detection | With one OpenBCI dongle plugged in, `python app.py` opens it without a COM argument. `cyton.find_dongle()` prefers FTDI (VID 0x0403) ports whose description mentions OpenBCI / FT231X / RFduino and never returns the band's ESP32-S3 port (VID 0x303A). `--board COMx` overrides. | tests/test_cyton.py (port scoring), manual: TEST_PLAN M-1 |
| FR-2 | Board handshake | `CytonBoard` soft-resets with `v`, waits up to 6 s for `$$$`, logs the banner lines, and raises a readable error naming the port when no banner arrives. | tests/test_cyton.py (banner parse), manual: M-2 |
| FR-3 | 8 and 16 channels | Daisy is detected from the banner ("On Daisy ... Device ID"); 8 ch at 250 Hz or 16 ch at 125 Hz per channel. `--channels 8` forces 8 ch on a Daisy board. Daisy packet halves are merged using `daisy_even_is_upper`; the flag can be flipped in `config.json`. | tests/test_cyton.py (packet parse, Daisy merge), manual: M-5 |
| FR-4 | Packet decoding and scaling | 33-byte packets (`A0 ... C0-CF`) decode to uV with 4.5 V / 24 / (2^23 - 1) per count; accelerometer at 0.002 g / 16 per count; dropped packets counted from the sample-number gap; resync on a bad header byte. | tests/test_cyton.py |
| FR-5 (v0.2) | Display filters match the OpenBCI GUI defaults; the index has its own | Default display chain: 60 Hz notch (plus its 2nd harmonic when below Nyquist), band-pass 5-50 Hz (two cascaded biquads per edge). Notch selectable 0/50/60 and band edges settable live via `set_filter`; the chain is rebuilt with fresh state. The display filter never touches the flow index: the index's spectrum uses a fixed, stateless chain of the selected notch + 1-45 Hz (`analysis_hi_hz`) built per epoch (`Pipeline._epoch`). | tests/test_dsp.py (notch attenuation, band-pass response), manual: M-4 |
| FR-6 | Quality flags | Per channel, from the raw signal of the current 2-s epoch: `railed` at >= 90 % of full scale (~187 500 uV), `near` at >= 75 %, `flat` when std < 0.05 uV, else `good`. Shown in the time-series widget; a non-good channel is excluded from the flow index for that epoch. | tests/test_dsp.py (quality thresholds), manual: M-3 |
| FR-7 (v0.2) | Spectra and band powers | Every 2-s epoch: (a) display: Hann PSD (uV^2/Hz) of the last 2 s up to 60 Hz, absolute and relative delta/theta/alpha/beta/gamma per channel, published in the `analysis` event; (b) index: Welch PSD of the last 10 s (`index_window_s`) from 2-s Hann segments (`index_seg_s`) at 50 % overlap with artifact segments dropped (`dsp.welch`), 0.5 Hz bins, bands `theta_fm` 4-7 and `alpha_hi` 10-13 Hz relative to the 1-45 Hz total (`dsp.INDEX_BANDS`, `dsp.TOTAL_BAND`), plus theta 4-8 / alpha 8-13 / beta 13-30 from the same spectrum for the covariates. | tests/test_dsp.py (PSD of a known sine, band integration); `welch` / `band_powers_of`: no unit test yet (TEST_PLAN gap), pipeline inspection + `--sim` integration ordering |
| FR-8 (v0.2) | EEG flow index definition is exposed | `FlowIndex.update()` returns `flow_eeg`, `flow_eeg_alt`, `artifact`, `theta_frontal_rel`, `alpha_cp_rel`, `beta_rel`, `engagement_index`, `theta_alpha_ratio`, `z_theta`, `z_alpha`, `z_beta`, `baseline_ready`, `baseline_state`, `n_good`, `frontal_sites`, `<band>_rel_mean`; the pipeline adds `t`, `p2p_uv`, `n_segments_used`. `flow_eeg = sigmoid(w_theta * z_theta - w_alpha * |z_alpha| - w_beta * z_beta)` with weights 1.0 / 0.0 / 0.0 from `config.json` `flow_index` (`set_flow_weights` for exploration only); `flow_eeg_alt = sigmoid(z_theta - 0.5 * |z_alpha|)`. The full definition is `docs/EEG_FLOW_INDEX.md`. | tests/test_flow_index.py |
| FR-9 (v0.2) | Fixed eyes-open rest baseline | Each log component is z-scored against the mean / SD collected during the protocol block flagged `baseline` (`FlowIndex.start_rest()` / `end_rest()`, driven by `App.on_protocol_event`), frozen at block end when >= `warmup_epochs` (15) clean epochs were collected (`baseline_state` = `rest-frozen`). Before that, and in sessions without a protocol, the expanding session mean / SD is used with z = 0 for the first 15 epochs. `baseline_mode` `session` and `rolling` (150 epochs) exist but are not the registered mode. | tests/test_flow_index.py (`TestBaseline`, `TestRestProtocol`) |
| FR-10 | Band sources | The band's flow score can be taken from Supabase (`SupabaseBandLink`), direct BLE (`BleBandLink`), USB (`BandLink`), the simulator (`SimBandLink`), or none, chosen with `--band` or `set_band_source`, swapped at run time by `BandManager` without restarting the EEG stream. | tests/test_supabase_link.py, tests/test_band_ble.py, manual: M-6, M-7 |
| FR-11 | Band sample semantics | Every source produces the same sample dict (`t`, `flow`, `hr`, `anom`, `held`, `settling`, `asleep`, `poor_contact`, `window`, ...). `flow` is `null` for a no-reading frame; `held` is true for a HIGH_RISK display hold (`mode == 1`) or LOW_RISK with window state unavailable; `settling` is derived for BLE/USB and always false for Supabase. | tests/test_band_ble.py (`decode_state`), tests/test_supabase_link.py (`row_to_sample`) |
| FR-12 | Wearer selection | With the Supabase source, `GET /api/wearers` lists (user, band) pairs seen in the last 24 h, newest first, with short id, band name, last sample age and rows in the last hour; the browser can pick one and the link restarts filtered on `user_id` and/or `band`. | tests/test_supabase_link.py (`wearers()` aggregation), manual: M-6 |
| FR-13 (v0.2) | Pairing at the band's cadence (secondary) | For each band sample with a non-null `flow` that is not `held`, `settling`, `asleep` or `poor_contact`, the EEG flow index (non-artifact epochs only) is averaged over the `pair_window_s` seconds before the band timestamp (60 s Supabase, 10 s BLE/USB/sim) and one pair is stored. Pairs feed the secondary epoch-level statistics, not the verdict. | tests/test_report.py (pairing on CSVs), pipeline inspection |
| FR-14 | Live epoch-level statistics with CI (secondary) | `stats` holds `n_pairs`, Pearson `r`, a bootstrap 95 % CI (500 resamples, null below 8 pairs), `r_last_5min`, MAE, mean band-minus-EEG offset, a lag sweep from -180 to +180 s in 10-s steps with the best lag, and felt-flow correlations (`felt.r_band`, `felt.r_eeg`, from 3 marks). | tests/test_report.py (pearson, bootstrap), manual: TEST_PLAN integration |
| FR-15 | Felt-flow marks | `mark` with kind `felt_flow` (0-1), `flow_start`, `flow_end`, `distracted`, `note` is appended to history, broadcast as an SSE `mark` event, and written to `marks.csv` while recording. | tests/test_recorder.py, manual: M-8 |
| FR-16 (v0.2) | Recording to CSV | `record_start` creates `sessions/<stamp>_<label>/` with `session.json`, `eeg_raw.csv`, `epochs.csv`, `band.csv`, `marks.csv`, `task.csv`; writes come from a queue thread so acquisition never blocks on disk; `record_stop` closes the files. Label limited to `[A-Za-z0-9_-]{0,32}`. `protocol_start` starts a recording automatically (label = protocol name) when none is running. | tests/test_recorder.py, manual: M-8 |
| FR-17 (v0.2) | Offline report with block-level gates | `report.py <session>` scores the session per block from `epochs.csv`, `band.csv`, `marks.csv` (block marks and `rating` marks), `task.csv` and `session.json`; prints the manipulation check (FSS, `demand`, accuracy per condition), the EEG reference check, the band's condition means and ordering, the block-level Spearman rho with n blocks, covariates and exclusions; applies the pre-registered verdict logic of `docs/VALIDATION_PROTOCOL.md` section 7 (PASS = manipulation ok and band highest in flow vs both others and rho >= 0.5 with >= 6 blocks; FAIL = manipulation ok but the band fails; INCONCLUSIVE otherwise); writes `report.md` + `report.json`. The v0.1 epoch-level statistics remain as secondary output. `GET /api/report?session=` runs it. | tests/test_report.py (gate logic on synthetic CSVs), manual: M-8 |
| FR-18 (v0.2) | Browser widgets | Experiment panel (protocol picker, START / NEXT / STOP, schedule strip, instruction, task widget, self-report status), time series (5/10/20 s), FFT, band power, head plot, flow comparison with block means, band panel, felt-flow controls, sessions list + report view, all fed only by `/events` and the JSON API in `docs/API.md`. | manual: TEST_PLAN integration (`--sim`), M-11, M-12 |
| FR-19 (v0.2) | Simulator | `--sim` runs `SimBoard` (synthetic EEG whose theta/alpha/beta follow a hidden flow state) and `SimBandLink` (that state + noise, 20 s lag, every 2 s). While a protocol runs, `App.on_protocol_event` calls `SimBoard.set_condition()` so the hidden state eases (~20 s) to the condition's level (`CONDITION_FLOW`: rest 0.40, boredom 0.25, flow 0.85, overload 0.30, work 0.60); without a protocol it drifts slowly. | tests/test_cyton.py (SimBoard shape/rate), TEST_PLAN integration |
| FR-20 | OpenBCI GUI mirror | `--source udp` reads the GUI's Networking widget `timeSeriesRaw`/`timeSeriesFilt` JSON datagrams on 127.0.0.1:`udp_port` into the same `SampleBuffer`. | manual: M-9 |
| FR-21 (v0.2) | Protocol runner | `ProtocolRunner` (`protocol.py`) builds a schedule from `protocols.json` (`build(name, seed)`): `shuffle` groups are permuted per repetition from the seed (default: session start time), the same condition never runs twice in a row, a `between` pause is inserted between task blocks and never after the last one, every block gets `index`, `rating`, `baseline`, `task` defaults. `start` runs the blocks on a daemon thread, each for its `duration_s` (checked every 0.25 s); `next` ends the current block now; `stop` aborts (block marked `aborted`, no rating requested). Transitions are marks (`protocol_start` with seed and order, `block_start` / `block_end` with the condition, `protocol_end` / `protocol_stop`) and SSE `protocol` events (`block_start`, `rating_due`, `block_end`, `rated`, `done`, `stopped`). `status()` reports the schedule, current block, remaining seconds, pending rating and the available protocols with total minutes. A second `start` while active raises. | tests/test_protocol.py |
| FR-22 (v0.2) | Difficulty-ladder protocol | `difficulty_ladder`: 3-min eyes-open rest flagged `baseline`, 1-min eyes-closed rest, two rounds of {boredom, flow, overload} 6-min arithmetic blocks with ratings, 60-s pauses between task blocks, 2-min final rest (14 blocks, 47 min). `sim_quick`: the same shape with 60-s rest / 60-s blocks / 20-s pauses. `free_work`: 3-min baseline then 8 x 5-min work blocks with ratings (not gated). | tests/test_protocol.py (layout, counterbalancing, totals) |
| FR-23 (v0.2) | In-browser arithmetic task | `static/app.js` runs the task named by the block: `arithmetic_easy` (single-digit additions, new problem every 4 s), `arithmetic_adaptive` (levels 1-12 from level 4; 2 correct -> up, 1 wrong -> down; 10-s soft limit; target 70-85 % correct), `arithmetic_hard` (level 12, 6-s hard limit). Each answer posts `trial` (`block_index`, `task`, `level`, `problem`, `answer`, `response`, `correct`, `rt_ms`, `t`); the server adds the current condition and writes `task.csv` while recording. The widget shows running accuracy and level and is cleared on `done` / `stopped`. | manual: M-11; tests/test_recorder.py (`trial` rows) |
| FR-24 (v0.2) | Self-report (Flow Short Scale) | On `rating_due` the browser opens a dialog with the 10 FSS items (1-7), the `demand` item (1 too low / 2 just right / 3 too high) and the 0-1 `flow_overall` slider; submitting posts `rating` (`block_index`, `items`). `ProtocolRunner.rate` stores it, clears `pending_rating`, writes a mark of kind `rating` whose value is JSON (`block`, `condition`, items) and emits `rated`; `Pipeline.mark` parses the mark into `pipeline.ratings`. The dialog can be dismissed (no rating stored). | tests/test_protocol.py (`rate`), tests/test_pipeline_blocks.py (`TestRatingMark`), manual: M-12 |
| FR-25 (v0.2) | Artifact rejection | A 2-s Welch segment is dropped when any enabled `good` channel exceeds 150 uV peak-to-peak (`artifact_p2p_uv`) or 100 uV absolute (`artifact_abs_uv`) after the analysis filter; an epoch with fewer than `ceil(index_min_clean_fraction * n_segments)` (5 of 9) clean segments is an artifact epoch: `flow_eeg` null, `artifact` true, nothing pushed into the baselines, not in `eeg_hist`, still written to `epochs.csv` with `n_segments_used`. `flow_status()` reports `artifact_epochs`. | tests/test_flow_index.py (`TestArtifacts`: the flag's effect on index and baselines); the segment `reject` rule in `Pipeline._epoch` / `dsp.welch`: inspection + manual M-13 (no unit test yet, TEST_PLAN gap) |
| FR-26 (v0.2) | Block-level statistics | `Pipeline.on_protocol` keeps a block table (`index`, `condition`, `t0`, `t1`, `baseline`) from `block_start` / `block_end` / `stopped`. `_block_stats()` gives per-block means of the EEG index (non-artifact epochs), the band's usable samples and the FSS core items (all rating items except `demand` and `flow_overall`), skipping `pause` blocks and blocks shorter than 30 s; per-condition means and `n_blocks`; an `ordering` string per measure over non-rest conditions; the Spearman `block_rho` between EEG and band block means with `n_blocks`, null below 4 blocks. Published as `stats.blocks`. | tests/test_pipeline_blocks.py |
| FR-27 (v0.2) | Montage preset | `config.json` `labels_8_flow` (Fz F3 F4 Cz C3 C4 P3 P4); `python app.py --montage flow` substitutes it for `labels_8` and logs `[montage] 8-ch flow montage: ...`; `session.json` stores the labels in use. Site selection (`FlowIndex.sites`) then uses Fz F3 F4 for theta and Cz C3 C4 P3 P4 for upper alpha; on the factory montage it falls back to Fp1 Fp2 and C3 C4; on 16 ch to F7 F8 F3 F4 and C3 C4 P3 P4. | tests/test_flow_index.py (`TestSites`), app.py inspection, manual: M-14 |
| FR-28 (v0.2) | Baseline control from the protocol | The block flagged `baseline` starts rest collection at `block_start` and freezes at `block_end` (`App.on_protocol_event`); the log says `[protocol] collecting the resting baseline` then `[protocol] baseline rest-frozen`; `flow_status()` and the flow widget show `baseline_state`. Epochs during rest that are artifacts are not collected. | tests/test_flow_index.py (`TestRestProtocol`), manual: M-13 |

## Non-functional

| ID | Requirement | Acceptance criterion | Verified by |
|---|---|---|---|
| NFR-1 | Localhost only | The HTTP server binds 127.0.0.1; no route accepts a remote origin; the UDP source binds 127.0.0.1. | server.py / openbci_udp.py inspection, manual: M-10 |
| NFR-2 | No secrets in the repo | Supabase credentials come only from `%USERPROFILE%\.bioproxal\supabase.env`; the USB master key only from `%USERPROFILE%\.bioproxal\master.key`. `.gitignore` excludes `*.env`, `*.key`. The key is never sent to the browser. | supabase_link.py / band_link.py inspection; `.gitignore` |
| NFR-3 | Read-only toward the band | No code path sends a baseline reset, log clear, flash or any write to the band: BLE subscribes to STATE only; USB only unlocks, keeps alive, reads `[pub]` lines and locks on close. | band_ble.py / band_link.py inspection; tests/test_band_ble.py has no write call |
| NFR-4 | Read-only toward Supabase | Only `GET /rest/v1/wearable_samples` with `select`; no insert/update/delete. | supabase_link.py inspection; tests/test_supabase_link.py |
| NFR-5 | Pure Python dependencies | Runtime needs only numpy and pyserial (bleak optional). No scipy, pandas, BrainFlow or other packages with native DLLs that Windows Smart App Control blocks. | requirements.txt; CI installs only that file |
| NFR-6 | Python 3.12+ | Tests pass on 3.12 and 3.14 on Windows and Ubuntu. | .github/workflows/ci.yml |
| NFR-7 (v0.2) | Real-time budget | On a laptop, the `samples` SSE event keeps up at 250 Hz x 16 ch; an epoch (display PSD + 9-segment Welch + flow index) completes well under 2 s; block stats are recomputed only on marks and band samples; the UI stays responsive with 4 h of history. | manual: TEST_PLAN integration (packet count grows at board rate, `dropped` stays 0) |
| NFR-8 (v0.2) | Session privacy | `sessions/` is git-ignored; report outputs stay inside the session folder; task answers and self-reports are part of the session; no session content is uploaded anywhere. | `.gitignore`; manual: M-8 |
| NFR-9 (v0.2) | Honest reporting | The report's verdict is computed only from the pre-registered gates; the index weights, baseline mode and artifact thresholds are stored in `session.json` so a later change is visible; `flow_eeg_alt` is printed as exploratory and never gates; a FAIL is written as FAIL; a failed manipulation check is INCONCLUSIVE, not FAIL. | tests/test_report.py; docs/VALIDATION_PROTOCOL.md |
| NFR-10 | Graceful degradation | A missing dongle, band, credential file or `bleak` reports a clear error in the status bar and the rest of the app keeps working (EEG-only or band-only). A protocol can run with band source `none` (EEG and self-report only). | manual: M-1, M-6, M-7 |
| NFR-11 | Browser contract stability | Any change to routes or event payloads is made in `docs/API.md` first. | review |
| NFR-12 (v0.2) | Pre-registration lock | The index definition (`docs/EEG_FLOW_INDEX.md` section 6), the protocol schedule and the gates are fixed before a series; any change is a version bump, a dated entry in the protocol's change table, and a re-run of the earlier sessions labelled exploratory. | docs/EEG_FLOW_INDEX.md, docs/VALIDATION_PROTOCOL.md, CHANGELOG.md |
| NFR-13 (v0.2) | Block timing | A block ends within 0.25 s of its `duration_s` (the runner polls `_advance` at 0.25 s); block marks carry the server clock, the same clock as the EEG epochs, so block windows and epochs align without a lag correction. | tests/test_protocol.py (tiny blocks run through in order), protocol.py inspection |
| NFR-14 (v0.2) | Participant-facing screen | During a protocol the experiment panel shows only the instruction, the task and the timer; statistics stay in other panels so the participant is not shown the live index during a block. | manual: M-11 |
