# Requirements

Each requirement has an acceptance criterion and a verification pointer: a test module
under `tests/`, a manual check in `docs/TEST_PLAN.md` (M-n), or a code/doc inspection.

## Functional

| ID | Requirement | Acceptance criterion | Verified by |
|---|---|---|---|
| FR-1 | Plug-and-play dongle detection | With one OpenBCI dongle plugged in, `python app.py` opens it without a COM argument. `cyton.find_dongle()` prefers FTDI (VID 0x0403) ports whose description mentions OpenBCI / FT231X / RFduino and never returns the band's ESP32-S3 port (VID 0x303A). `--board COMx` overrides. | tests/test_cyton.py (port scoring), manual: TEST_PLAN M-1 |
| FR-2 | Board handshake | `CytonBoard` soft-resets with `v`, waits up to 6 s for `$$$`, logs the banner lines, and raises a readable error naming the port when no banner arrives. | tests/test_cyton.py (banner parse), manual: M-2 |
| FR-3 | 8 and 16 channels | Daisy is detected from the banner ("On Daisy ... Device ID"); 8 ch at 250 Hz or 16 ch at 125 Hz per channel. `--channels 8` forces 8 ch on a Daisy board. Daisy packet halves are merged using `daisy_even_is_upper`; the flag can be flipped in `config.json`. | tests/test_cyton.py (packet parse, Daisy merge), manual: M-5 |
| FR-4 | Packet decoding and scaling | 33-byte packets (`A0 ... C0-CF`) decode to uV with 4.5 V / 24 / (2^23 - 1) per count; accelerometer at 0.002 g / 16 per count; dropped packets counted from the sample-number gap; resync on a bad header byte. | tests/test_cyton.py |
| FR-5 | Display filters match the OpenBCI GUI defaults | Default chain: 60 Hz notch (plus its 2nd harmonic when below Nyquist), band-pass 5-50 Hz (two cascaded biquads per edge), the same defaults as the OpenBCI GUI. Notch selectable 0/50/60 and band edges settable live via `set_filter`; the chain is rebuilt with fresh state. The display filter never touches the flow index: the index's spectrum uses a fixed notch + 1-55 Hz analysis filter. | tests/test_dsp.py (notch attenuation, band-pass response), manual: M-4 |
| FR-6 | Quality flags | Per channel, from the raw signal of the current epoch: `railed` at >= 90 % of full scale (~187 500 uV), `near` at >= 75 %, `flat` when std < 0.05 uV, else `good`. Shown in the time-series widget; a non-good channel is excluded from the flow index for that epoch. | tests/test_dsp.py (quality thresholds), manual: M-3 |
| FR-7 | Spectrum and band powers | Every 2-s epoch: Hann PSD (uV^2/Hz) up to 60 Hz, absolute and relative delta/theta/alpha/beta/gamma per channel, published in the `analysis` event. | tests/test_dsp.py (PSD of a known sine, band integration) |
| FR-8 | EEG flow index definition is exposed | `FlowIndex.update()` returns `flow_eeg` and every component (`theta_frontal_rel`, `alpha_posterior_rel`, `beta_rel`, `engagement_index`, `theta_alpha_ratio`, `z_theta`, `z_alpha`, `z_beta`, `baseline_ready`, `n_good`, `<band>_rel_mean`); the formula and weights are documented in `flow_index.py` and `docs/ARCHITECTURE.md`; weights are set from `config.json` and `set_flow_weights`. | tests/test_flow_index.py |
| FR-9 | Rolling personal baseline | Each component is z-scored over the last `baseline_epochs` (150 = 5 min) epochs; z = 0 until `warmup_epochs` (15) have been seen; `baseline_ready` reports this. | tests/test_flow_index.py |
| FR-10 | Band sources | The band's flow score can be taken from Supabase (`SupabaseBandLink`), direct BLE (`BleBandLink`), USB (`BandLink`), the simulator (`SimBandLink`), or none, chosen with `--band` or `set_band_source`, swapped at run time by `BandManager` without restarting the EEG stream. | tests/test_supabase_link.py, tests/test_band_ble.py, manual: M-6, M-7 |
| FR-11 | Band sample semantics | Every source produces the same sample dict (`t`, `flow`, `hr`, `anom`, `held`, `settling`, `asleep`, `poor_contact`, `window`, ...). `flow` is `null` for a no-reading frame; `held` is true for a HIGH_RISK display hold (`mode == 1`) or LOW_RISK with window state unavailable; `settling` is derived for BLE/USB and always false for Supabase. | tests/test_band_ble.py (`decode_state`), tests/test_supabase_link.py (`row_to_sample`) |
| FR-12 | Wearer selection | With the Supabase source, `GET /api/wearers` lists (user, band) pairs seen in the last 24 h, newest first, with short id, band name, last sample age and rows in the last hour; the browser can pick one and the link restarts filtered on `user_id` and/or `band`. | tests/test_supabase_link.py (`wearers()` aggregation), manual: M-6 |
| FR-13 | Pairing at the band's cadence | For each band sample with a non-null `flow` that is not held and not asleep, the EEG flow index is averaged over the `pair_window_s` seconds before the band timestamp (60 s Supabase, 10 s BLE/USB/sim) and one pair is stored. | tests/test_report.py (pairing on CSVs), pipeline inspection |
| FR-14 | Live statistics with CI | `stats` holds `n_pairs`, Pearson `r`, a bootstrap 95 % CI (500 resamples, null below 8 pairs), `r_last_5min`, MAE, mean band-minus-EEG offset, a lag sweep from -180 to +180 s in 10-s steps with the best lag, and felt-flow correlations (`felt.r_band`, `felt.r_eeg`, from 3 marks). | tests/test_report.py (pearson, bootstrap), manual: TEST_PLAN integration |
| FR-15 | Felt-flow marks | `mark` with kind `felt_flow` (0-1), `flow_start`, `flow_end`, `distracted`, `note` is appended to history, broadcast as an SSE `mark` event, and written to `marks.csv` while recording. | tests/test_recorder.py, manual: M-8 |
| FR-16 | Recording to CSV | `record_start` creates `sessions/<stamp>_<label>/` with `session.json`, `eeg_raw.csv`, `epochs.csv`, `band.csv`, `marks.csv`; writes come from a queue thread so acquisition never blocks on disk; `record_stop` closes the files. Label limited to `[A-Za-z0-9_-]{0,32}`. | tests/test_recorder.py, manual: M-8 |
| FR-17 | Offline report with gates | `report.py <session>` recomputes pairs and stats from the CSVs, applies the pre-registered gates (r >= 0.5, CI lower bound > 0, n >= 20; INCONCLUSIVE below 20 pairs), prints the secondary metrics, and writes `report.md` + `report.json` in the session folder. `GET /api/report?session=` runs it. | tests/test_report.py (gate logic on synthetic CSVs), manual: M-8 |
| FR-18 | Browser widgets | Time series (5/10/20 s), FFT, band power, head plot, flow comparison, band panel, felt-flow controls, sessions list + report view, all fed only by `/events` and the JSON API in `docs/API.md`. | manual: TEST_PLAN integration (`--sim`) |
| FR-19 | Simulator | `--sim` runs `SimBoard` (synthetic EEG whose theta/alpha/beta follow a hidden flow state) and `SimBandLink` (that state + noise, 20 s lag, every 2 s) so the whole pipeline and report can be exercised with no hardware. | tests/test_cyton.py (SimBoard shape/rate), TEST_PLAN integration |
| FR-20 | OpenBCI GUI mirror | `--source udp` reads the GUI's Networking widget `timeSeriesRaw`/`timeSeriesFilt` JSON datagrams on 127.0.0.1:`udp_port` into the same `SampleBuffer`. | manual: M-9 |

## Non-functional

| ID | Requirement | Acceptance criterion | Verified by |
|---|---|---|---|
| NFR-1 | Localhost only | The HTTP server binds 127.0.0.1; no route accepts a remote origin; the UDP source binds 127.0.0.1. | server.py / openbci_udp.py inspection, manual: M-10 |
| NFR-2 | No secrets in the repo | Supabase credentials come only from `%USERPROFILE%\.bioproxal\supabase.env`; the USB master key only from `%USERPROFILE%\.bioproxal\master.key`. `.gitignore` excludes `*.env`, `*.key`. The key is never sent to the browser. | supabase_link.py / band_link.py inspection; `.gitignore` |
| NFR-3 | Read-only toward the band | No code path sends a baseline reset, log clear, flash or any write to the band: BLE subscribes to STATE only; USB only unlocks, keeps alive, reads `[pub]` lines and locks on close. | band_ble.py / band_link.py inspection; tests/test_band_ble.py has no write call |
| NFR-4 | Read-only toward Supabase | Only `GET /rest/v1/wearable_samples` with `select`; no insert/update/delete. | supabase_link.py inspection; tests/test_supabase_link.py |
| NFR-5 | Pure Python dependencies | Runtime needs only numpy and pyserial (bleak optional). No scipy, pandas, BrainFlow or other packages with native DLLs that Windows Smart App Control blocks. | requirements.txt; CI installs only that file |
| NFR-6 | Python 3.12+ | Tests pass on 3.12 and 3.14 on Windows and Ubuntu. | .github/workflows/ci.yml |
| NFR-7 | Real-time budget | On a laptop, the `samples` SSE event keeps up at 250 Hz x 16 ch; an epoch (PSD + flow index + stats) completes well under 2 s; the UI stays responsive with 4 h of history. | manual: TEST_PLAN integration (packet count grows at board rate, `dropped` stays 0) |
| NFR-8 | Session privacy | `sessions/` is git-ignored; report outputs stay inside the session folder; no session content is uploaded anywhere. | `.gitignore`; manual: M-8 |
| NFR-9 | Honest reporting | The report's verdict is computed only from the pre-registered gates; weights are stored in `session.json` so a later weight change is visible; a FAIL is written as FAIL. | tests/test_report.py; docs/VALIDATION_PROTOCOL.md |
| NFR-10 | Graceful degradation | A missing dongle, band, credential file or `bleak` reports a clear error in the status bar and the rest of the app keeps working (EEG-only or band-only). | manual: M-1, M-6, M-7 |
| NFR-11 | Browser contract stability | Any change to routes or event payloads is made in `docs/API.md` first. | review |
